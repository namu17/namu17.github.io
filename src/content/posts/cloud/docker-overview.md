## Docker
> 컨테이너 기술을 활용하여 애플리케이션을 개발 및 배포하기 위한 오픈 소스 가상화 플랫폼

## 컨테이너
커널을 제외한 애플리케이션과 실행에 필요한 모든 파일, 라이브러리, 의존성을 하나로 묶어 어디서든 동일하게 실행할 수 있도록 만든 격리된 소프트웨어 실행 환경입니다.

### VM과의 차이점
VM인 경우 Host OS 위에 Hypervisor를 통하여 Guest OS 전체를 가상화하는 방식입니다. 이에 따라 각 VM이 강한 격리를 제공하지만, 무겁고 느리며 Hypervisor를 거쳐야 하므로 하드웨어 자원을 사용할 때 성능 손실이 발생합니다.

반면 Docker 컨테이너는 Guest OS 없이 Host OS의 커널을 그대로 공유합니다. 컨테이너는 Host OS 위에서 실행되는 하나의 프로세스이며, 리눅스 커널의 namespace(프로세스에게 독립된 시스템 환경 제공)와 cgroups(CPU, 메모리, I/O 등의 리소스 사용량 제한) 기능을 통해 다른 프로세스와 격리됩니다. Docker 엔진은 이러한 컨테이너를 생성하고 실행, 관리하는 역할을 합니다.

따라서 Guest OS와 Hypervisor가 없기 때문에 성능 손실이 거의 없고, 용량 자체도 매우 작아 애플리케이션을 빠르게 배포하고 실행할 수 있습니다. 또한 컨테이너를 생성하고 삭제하는 과정이 간단하고 빠르기 때문에 확장성이 뛰어납니다. 그리고 개발 환경, 테스트 환경, 운영 환경을 똑같이 맞출 수 있어서 환경의 일관성 및 재현성을 제공합니다. 그러나 Host OS의 커널을 공유하기 때문에 커널 취약점을 이용해 컨테이너 내부에서 Host로 접근하는 컨테이너 탈출이 발생할 수 있습니다.

## Docker 아키텍처
Docker는 클라이언트-서버 아키텍처를 사용합니다. 클라이언트는 UNIX 소켓이나 네트워크 인터페이스를 통해 REST API로 Docker Daemon과 통신합니다. Docker Compose 또한 클라이언트의 하나로, 여러 컨테이너로 이루어진 애플리케이션을 다룰 때 사용합니다.

### Docker Daemon(`dockerd`)
API 요청을 받아서 이미지, 컨테이너, 네트워크, 볼륨과 같은 Docker 오브젝트를 관리합니다. 서비스를 관리하기 위해 다른 Docker Daemon과 협력할 수 있습니다.

### Docker Client(`docker`)
대부분의 사용자가 Docker를 다루는 방법으로, `docker run`과 같은 명령어를 입력하면 클라이언트가 이를 `dockerd`에 보내 실행시킵니다. 하나의 클라이언트는 여러 데몬과 통신할 수 있습니다.

### Docker Registry
이미지를 저장하는 곳으로, 공개 레지스트리인 Docker Hub가 기본값이며, 개인(프라이빗) 레지스트리도 운영할 수 있습니다. `docker pull`이나 `docker run`을 실행하면 설정된 레지스트리에서 이미지를 받아오고, `docker push`를 실행하면 이미지를 레지스트리에 올립니다.

### Docker Objects
> Docker를 사용하면서 만들고 쓰는 이미지, 컨테이너, 네트워크, 볼륨, 플러그인 등을 말합니다.

#### Images
Docker 컨테이너를 만드는 방법이 담긴 읽기 전용 템플릿입니다. Dockerfile의 명령어 하나하나가 레이어를 하나씩 만들고, 이미지를 다시 빌드할 때는 바뀐 레이어만 새로 빌드합니다.

#### Containers
이미지를 실행할 수 있는 상태로 만든 인스턴스입니다. 컨테이너를 생성, 시작, 중지, 이동, 삭제할 수 있고, 네트워크에 연결하거나 스토리지를 붙이거나, 현재 상태를 새 이미지로 저장할 수도 있습니다. 컨테이너는 기본적으로 격리되어 있으며, 컨테이너를 삭제할 때 저장하지 않은 상태는 사라집니다.

#### 예시) `docker run` 명령어
`docker run -i -t ubuntu /bin/bash`는 Ubuntu 컨테이너를 대화형으로 실행하는 명령어입니다. 해당 명령을 실행하면 Docker는 다음 순서로 동작합니다.

1. 로컬에 `ubuntu` 이미지가 없으면 설정된 레지스트리에서 받아옵니다.
2. 새 컨테이너를 생성합니다.
3. 컨테이너의 마지막 레이어로 읽기/쓰기가 가능한 파일 시스템을 할당합니다.
4. 기본 네트워크에 연결된 네트워크 인터페이스를 만들고 IP 주소를 할당합니다. 해당 네트워크는 Host의 네트워크 연결을 사용합니다.
5. 컨테이너를 시작하고 `/bin/bash`를 실행합니다. 해당 쉘은 사용자의 터미널에 연결됩니다.
6. `exit`를 입력하면 컨테이너가 중지되지만 삭제되지는 않습니다. 따라서 다시 시작하거나 삭제할 수 있습니다.
